## 2. 已有约束（来自本项目已发生的事实，不是猜测）

### 2.1 开场动画 —— 这是第二次做，第一版已被拆掉

2026-10-19 上午刚删除旧开场页 `public/opening/index.html`。原因是它依赖 **WebGPU**：
显卡没开硬件加速的机器会停在「此方世界需要一尊支持 WebGPU 的法器」，**只能靠右上角「进入网站」手动逃出**。

新版硬约束（任何一条不满足就不做）：

- 不依赖 WebGPU / WebGL2；纯 CSS + 可选 Canvas2D 即可
- 首帧 150ms 内出现，总时长 ≤ 1.6s，**不遮挡任何可交互内容**（不用全屏遮罩锁滚动）
- 任意点击 / 按 Esc / 滚动即跳过
- `localStorage` 记住，同一浏览器只播一次；提供「重播」入口
- `prefers-reduced-motion: reduce` 直接跳过，不做降级动画
- 首屏 LCP 不被它拖慢：动画层 `pointer-events:none`，内容先渲染

### 2.2 换页动画

- 路由里 `EditPage`、`ReviewPage`、`SurveyFillPage` 是**懒加载**，切换时会有 Suspense fallback
- 动画必须与数据请求并行，**不能在动画期间阻塞请求**
- 优先 `document.startViewTransition`（Chrome 111+），不支持时降级为 160ms 淡入
- 返回/前进方向要区分（浏览器 popstate）

### 2.3 图标

现状：**整个站没有图标系统**，全部是文字按钮。新增需要：

- 1.5px 描边 / 24 格 / `currentColor` / 直角或 2px 圆角（与 `--radius: 2px` 一致）
- 至少 14 枚：文库、上传、编辑、审核、问卷、MC、云、AI、人、工具、投票、协议、定制、分享
- 需要 12px 与 20px 两个尺寸档

### 2.4 排版与布局

现有 token 只有字阶（12–44）、间距（4–72）、容器宽（1180 / 760），**没有栅格，也没有「工作台版式」**。
编辑台目前是表单纵向堆叠。重设计必须区分两种版式：

- **阅读版式**：单栏、760px、行高 1.85 —— 文库与阅读页用
- **工作台版式**：栅格、密度更高 —— 编辑台、审核台、工具、投票、资源页用

### 2.5 背景

现在是 `body` 的 `--texture` 单层（纸纹竖纹 / 墨夜径向晕），`background-attachment: fixed`。
重设计要点：

- 亮暗两套各自成立，不是同一张图调透明度
- 避免 `backdrop-filter` + fixed 大层的组合（低端机掉帧）
- 背景必须让位于正文对比度：正文对比度不低于 7:1

### 2.6 声音（与本项目已实测的结论对齐）

- **音乐**：MiniMax 音乐只有网页版，无 API（本项目实测过）
- **音效**：MiniMax 全线**没有音效模型**。只能走 CC0 素材库（freesound / pixabay）或本地合成
- 播放策略：默认静音；首次用户手势后才允许出声；站内没有自动播放 BGM
- 每段音频 ≤ 40kB（opus）或流式延迟加载，否则拖慢首屏

### 2.7 版本与各类计数（18–22）

**先说清现状：这五项今天一个都不存在。**

| 项 | 实测现状 |
|---|---|
| 版本 | `0.6.8` 只写在 `package.json`。`apps/web/src` 里 grep `version` **零命中** —— 界面从不显示版本 |
| 访客数 / 浏览数 | 全站没有。`apps/server/src` 里 grep `view_count`、`visitor` 只命中问卷模块的 `one_per_visitor` / `visitor_hash`，那些是「一份问卷同一浏览器只收一份」，不是站级计数 |
| 点赞数 | 不存在，连点赞这个动作都没有 |
| 每个用户的收藏数 | **收藏功能本身不存在** —— 所以这一项实际是「先收藏，再计数」两件事 |

设计约束：

- **访客 ≠ 浏览。** 访客是去重后的独立人，浏览是累加次数。两个数字必须分开显示；如果算出来一样，说明其中一个是假的（常见错法：拿 session 数当访客数）。
- **计数只能服务端写。** 前端上报的浏览数可伪造，一旦可伪造，这个数字就永久失去意义。
- **防放大。** 详情页每刷新 +1 会让「浏览数」退化成「刷新次数」。按 session 去重后再 +1，比裸计数可信。
- **可复用的是问卷那套 `visitorHash`**（`public.ts:39`，cookie/localStorage 的 vid + 请求头 hash），但问卷那个是 per-survey 的，站级访客要独立一份。
- **隐私边界**：IP **不落库**，只落 hash；这条要写进协议页（第 17 项），否则两件事会撞车。
- **版本号必须有单一来源。** 现在只有 `package.json` 一处；界面上要显示，就得从构建期注入，不能再手抄一份，否则第一次发版就会不一致。
- **收藏计数是「每用户」维度**，需要 `(user_id, document_id)` 唯一约束；点赞同理，但点赞要不要允许匿名、能不能取消，见第 3 节。

## 3. 需要坞主给的东西（等参考素材）

| 项 | 需要什么 | 没有它我能做到哪 |
|---|---|---|
| 虚拟角色 | 形态设定（纸偶 / 墨灵 / 机器灵）、名字、是否出现在每个页面 | 只能出 2–3 个草图方向 |
| 人员 | MC 名单来源（白名单 / 面板 API / 手工 JSON）；网站人员是否等于注册用户；要不要头像 | 卡片骨架 |
| 资源数据 | MC 用 RCON 还是面板 API；腾讯云用监控 API 还是手工录入；AI 用量从哪计数 | 布局与占位，**不填假数字** |
| 协议 | 签什么（投稿授权 / 隐私 / 社区规则）、签署后是否落库 | 页面框架 |
| 投票 | 投什么、谁有票权、一人一票怎么判 | 页面框架 |
| 工具页 | 放哪些工具（现有编辑台的导出/问卷算不算） | 页面框架 |
| 定制页 | 定制对象（主题 / 封面 / 个人页 / 邀请码） | 页面框架 |
| MC 内 AI | 指服务器里的 AI bot/NPC，还是「服务器算力被 AI 占了多少」——**这两种是完全不同的页面** | 无法开工 |
| 版本号 | 显示在哪（页脚 / 关于页）、要不要同时显示更新日期、版本从 `package.json` 还是别的源注入 | 能做成构建期注入 + 页脚一行 |
| 访客 / 浏览口径 | 访客按天去重还是永久去重；浏览算首页、详情页还是两者都算；数字要不要对外可见 | 表结构与写入点，**不出数字** |
| 点赞口径 | 要不要登录才能点；能不能取消；一人一份还是允许重复 | 只能定表结构 |
| 收藏 | 这一项要先确认「收藏」功能是否要做 —— 没有收藏就没有收藏数量 | 无法开工 |
